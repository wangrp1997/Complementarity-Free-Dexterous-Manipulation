# 证伪规范：接触歧义是否值得主动探索（L1–L4）

日期：2026-09-22
性质：**诊断性最简验证**。不是控制器设计，不是论文实验，不是新方法实现。

---

## 0. 待证伪的主张

**C**：在 Allegro 手内重定向任务中，允许观测（视觉位姿 + 本体感觉 + 四指尖触觉 + 已知 CAD）
无法唯一确定当前接触状态；该歧义会改变"下一步该执行哪个动作"；
且存在一个可执行动作能通过观测把该歧义消除。

C 分解为四级。任一级失败都否掉一个**具体子主张**，并指向不同的修法。

| 级 | 问题 | 失败含义 |
|---|---|---|
| L1 | 允许观测下是否存在多个相容的接触假设？ | 观测已唯一确定接触状态 → 触觉消歧前提不成立 |
| L2 | 这些假设在任务目标方向上是否给出不同的可达进展？ | 歧义真实但与任务无关 → 加多少触觉都没用 |
| L3 | 这些假设是否给出不同的最优动作？ | 歧义真实且任务相关，但动作相同 → 无需探索 |
| L4 | 是否存在合法探测动作能区分它们？ | 单步不可分 → 定理级负面结果，指向多步或换接口 |

C 只在 L1–L4 全通过时成立。**每一级结论必须带上"在什么表示、什么动作接口、什么预算下"**，
否则是过度声明。

---

## 1. 允许观测集（白名单 / 黑名单）

**允许（控制器可见）**

- `state[0:7]`：物体位置 + 四元数（视觉位姿）
- `state[7:23]`、`joint_velocity`：手部关节位置与速度（本体感觉）
- `tactile` (4x14)：四指尖聚合量（激活标志、载荷、力、力矩、法向合力）
- `contact_records`：**已被感知**的指尖接触点/法向/力/力矩（物体坐标系）
- `action`、`base_action`：已执行的动作
- 手与物体的 CAD 几何、运动学模型（离线已知）

**禁止作为控制器输入（仅可用于事后审计）**

- `labels.npz` 的全部内容，尤其 `contact_truth_records`、`integration_state`、`n_ground_contacts`
- `diagnostics` 中的 `n_object_contacts` / `n_palm_contacts` / `n_other_object_contacts`
- 物体质量、惯量、质心、摩擦系数、`physical_parameters`
- 未来帧（`next_*` 只在离线标签角色中使用，且必须显式标注）

审计标记：若某步必须读取黑名单字段，必须显式写出 `PRIVILEGED: <field>` 并说明用途
（例如"仅用于覆盖率审计，不进入相容集构造"）。

## 2. 记号与核心关系

每个基线帧 t：

- `q_t`：`state`，布局 `[obj_pos(3), obj_quat_wxyz(4), hand_qpos(16)]`，共 23
- `qv_t`：MuJoCo 速度，布局 `[hand_qvel(16), obj_twist(6)]`，共 22
- `dq_t = q_{t+1}[7:23] - q_t[7:23]`：**实际**关节位移（不是 `action`）
- `x_t in R^6`：物体增量位移，由 `q_t, q_{t+1}` 的位置差与四元数对数映射得到

用实际 `dq` 而非 `action`：跟踪误差 34.7%–51.4%，用 `action` 会把伺服误差混进模式残差。

FREE 的接触检测对每个候选接触 c 给出

    jac_c = [ J_c | A_c ] in R^{1x22},   jac_c = jac^normal_c + mu * jac^friction_c

列按 `qv` 顺序切分为手部 `J_c in R^{1x16}` 与物体 `A_c in R^{1x6}`。
FREE 的互补自由约束即 `jac_c @ qv = 0`（软约束，`phi_c` 为间隙）。

对假设 h（一组接触 + 每个接触的 mu 取值）堆叠得到：

    A_h x_t = - J_h dq_t

残差 `r_h = ||A_h x_t + J_h dq_t||_2`。**残差中不出现质量、惯量、摩擦系数。**
这与"无需物体动力学"是同一件事，不是近似借口。

---

## 3. 候选接触生成（只用允许观测）

1. `contact_records` 中已感知的指尖接触：**每个假设必含**。
2. 其余手部几何（palm、指节、非指尖指段）：用已知 CAD + 观测位姿 + `mj_forward`/`mj_collision`，
   取与物体表面距离小于 `d_max` 的几何为**候选**。候选只表示"可能是支撑"，**不表示有力**。
3. 排除与地面（plane geom）的接触假设：`qualify_snapshot` 已剔除着地快照。
4. 每个候选的模式取 `mu in {0, mu_obj}`：
   - `mu = 0`：纯法向约束（黏着/不动）
   - `mu = mu_obj`：FREE 的摩擦加权约束（摩擦饱和/滑移）

**枚举预算**：候选按距离升序取前 `K_max` 个（默认 6）。
每个子集要求 `rank(A_h) = 6`（能约束全部 6 个物体自由度），否则丢弃。
保留**极小**接触集（去掉任一接触后秩不足）与全候选集。
必须报告：`K_max`、`d_max`、丢弃数、每帧保留假设数。

## 4. L1：歧义存在性

对每个基线帧计算 `{r_h}`。

- `r_min = min_h r_h`
- **相容集** `H_c = { h : r_h <= max(tau_abs, kappa * r_min) }`，默认 `kappa = 3`
- `tau_abs` **不得凭空设定**：由残差谱现场标定，并报告取值与依据

**通过判据（同时满足）**

1. 覆盖率审计：每帧的真值接触集（`contact_truth_records`，**仅审计用**）必须被**某个**
   `h in H_c` 覆盖。若否，则假设空间**设定错误**，L1 结论无效，必须先修表示。此条最先检查。
2. `|H_c| > 1` 的帧比例显著大于 0（报告具体数字）。
3. 相容集中至少存在两个**结构不同**的假设（接触集合不同，或 mu 模式不同），而非仅数值抖动。

**失败含义**：允许观测已唯一确定接触状态 → C 的前提不成立。

---

## 5. L2：任务相关性

在状态 `q_t` 上对 FREE 的任务代价（位置项 `||p - p_tgt||^2` 与四元数项
`1 - (quat . quat_tgt)^2`）求对物体位移的梯度：

    g_t = dJ_task/dx at x=0,  in R^6

（手部关节固定，仅对物体位姿求导。）

假设 h 下的可达集合由动作盒 D（`action_bounds` ∩ `||u||inf <= u_max`）决定：

    x = -(A_h^T A_h)^{-1} A_h^T J_h u  =:  T_h u
    m_h = max_{u in D} g_t^T T_h u

（盒上线性函数的极大值逐坐标取得，闭式。）

**通过判据**：`spread_h(m_h) = max_h m_h - min_h m_h > tau_task`。

阈值 `tau_task` 以当前状态的任务代价尺度归一化后报告（例如相对 `J_task(q_t)` 的一阶可改进量），
不写成绝对数值。

**附加报告（比单个数更重要）**：是否出现**可行性反转**——
存在 h1 使 `m_h1 > 0`（能朝目标推进）而 h2 使 `m_h2 <= 0`（朝目标推进不可行）。

**失败含义**：歧义真实但任务无关 → 探索无收益。

---

## 6. L3：动作分岔（命门）

带控制正则的最优动作：

    u*_h = argmax_{u in D} [ g_t^T T_h u - lambda ||u||_2^2 ]

`lambda` 取 FREE 控制代价的同一量级（须报告取值），并同时报告 `lambda = 0` 的纯盒解作为对照，
避免结论依赖正则项。

**通过判据（满足其一即算分岔）**

1. 相对分歧：`||u*_h1 - u*_h2||_2 / diag(D) > tau_u`（默认 `tau_u = 0.10`）
2. 结构分歧：主导坐标不同 / 激活手指集合不同 / 方向符号不同

只需报告"两两分歧"的分布，不需要聚类。

**失败含义**：歧义真实、任务相关，但所有相容假设指向同一动作 →
**探索预算应为零**。这是"歧义存在 != 探索有用"的分界线，也是 C 的命门。

---

## 7. L4：可分性

对 L3 中真正分岔的假设对 (h1, h2)，找合法探测动作 `u_p in D_probe`：

    D_probe = D ∩ { ||u||inf <= eps_probe },   eps_probe in {0.002, 0.004} rad

（与已采集探针一致，便于用实测分支验证。）

预测的物体位移差 `dx = (T_h1 - T_h2) u_p`。

**通过判据**：存在 `u_p in D_probe` 使 `||dx|| > tau_obs`，
且**同时**检查接触集合是否变化（接触集合变化本身就是可观测量）。
`tau_obs` 由实测探针的响应尺度标定。

**实测验证（并行，独立于 L1–L3）**：`docs/data/tactile_probe_v2_review_20260920` 已有
4 个配对快照（mug nominal x1、mug unknown-dyn x2、stick nominal x1），每快照含基准 + 正负 eps
共 5 分支。用它直接回答"实际响应中有多少是可观测的"，并特别报告零响应情况
（stick nominal joint 1 的导数约 1e-14，即该方向探测的信息量严格为零）。

**失败含义**：单步不可分 → 指向多步探测、重新接触或更换感知接口，而非"再调调参数"。

## 8. 附加诊断

**A. 失败归因**：挑失败 trial，检查失败前后若干帧是否存在触觉可观测量签名
（接触脱开、载荷骤降、切向相对位移）。若失败时刻**没有任何可观测量签名**，
则该类失败不是接触信息问题，触觉探索救不了。结论：把该机制从相关失败模式中排除。

**B. Oracle 上界**：给候选控制器真值接触配置（labels 只作上界，不进控制器），
看它比 FREE 好多少。**若连知道全部接触真值都不比 FREE 强，问题就不在接触知识上**，
整个触觉故事跑偏，该去查动作空间、规划或控制。

# 附录 A：实测修正（2026-09-22）

本节由 `check_core_relation.py` 与 `check_discrimination.py` 在 cube nominal 前 8 帧上的实测结果驱动。
**以下修正优先于正文相应条款。** 保留正文原文以留修订痕迹。

## A.1 核心关系成立，但只在正确的尺度上

`A_h x = -J_h dq` 在真值接触集上成立，逐接触约束违反量约 `1e-3 ~ 4e-2`（物理单位，米/步）。
但这是**控制区间位移**尺度（baseline 动作幅度约 0.2 rad）的量级，
一阶线性化在此尺度上已经失效：

- 归一化 consistency 残差 `||A x + J dq|| / ||J dq||` 为 **0.42–1.05**（100% 量级）
- adequacy `||x_pred - x_obs|| / ||x_obs||` 约 **1.0**，即约束模型几乎没预测出物体运动
- 第 6、7 帧出现 `1e8` 量级，属数值病态

**结论**：L1 必须在**单个物理步**上做（还原 `state` + `joint_velocity`，设 `ctrl`，跑一次 `mj_step`，
用该步位移计算 `x` 与 `dq`），或直接使用 ε-探针分支（0.002 rad）。
**禁止**用控制区间位移做 L1 的假设评分。

## A.2 朴素残差有系统性偏差，必须用两侧判据

`r_h = ||A_h x + J_h dq||` 随行数减少而单调下降，因此**任何"删掉接触"的假设都会赢**。
实测：真值集、真值+伪接触、松开一个接触的切向，三者得分**没有可分性**。

改用两侧判据：

    consistency(h) = ||A_h x_obs + J_h dq|| / ||J_h dq||        越小越好
    adequacy(h)    = ||Pi_h (x_pred_h - x_obs)|| / ||Pi_h x_obs||   越小越好
    其中 Pi_h = 到 row(A_h) 的正交投影，x_pred_h = -pinv(A_h) (J_h dq)
    且必须同时报告 rank(A_h) 与 null_dim = 6 - rank(A_h)

零空间方向不计入残差——否则会**惩罚**真值假设（真值集经常不满秩）。

## A.3 秩条件修正（重要）

原稿第 3 节要求 `rank(A_h) = 6` 否则丢弃。实测 `rank(A_true)` = 3,6,5,6,6,6,6,6，
即 **2/8 帧的真值接触集不满秩**。原判据会直接丢掉真值假设。

修正为：允许 `rank(A_h) <= 6`，显式记录 `null_dim`，
并把所有涉及 `T_h` 的量写成**条件性结论**（"在约束能确定的子空间上……"）。

## A.4 L2 的修正

`T_h = -(A_h^T A_h)^{-1} A_h^T J_h` 在 `null_dim > 0` 时不可用，必须用 `pinv`。
自由度未被约束时，`g^T T_h u` 只给出受约束分量的进展，零空间分量方向未知，
**不得假定为零、也不得假定有利**。`m_h` 应报告为区间：

    m_h^pess = min  (自由分量取对任务最不利)
    m_h^opt  = max  (自由分量取对任务最有利)

spread 判定基于区间比较，避免"部分约束假设"与"完整约束假设"之间的不可比。

## A.5 结论纪律

若改到单步后仍无可分性，**如实写**"在本表示 + 单步线性化下，实测数据无法区分接触假设"，
并说明要改什么（表示 / 时间尺度 / 感知接口）。不得为了跑出正结果放宽阈值。

# 附录 B：判据作废与重建（2026-09-22，读源码后）

**附录 A 的残差判据（L1）与 `T_h` 映射（L2/L3）均已作废。** 保留原文以留修订痕迹。
本节说明为什么，以及替什么。

## B.1 根因：`A_h x = -J_h dq` 不是 FREE 的模型

`models/explicit_model.py::init_model` 的实际形式：

    b = [ m_obj * g  ;  K_robot @ cmd ]
    v_non_contact = Q^{-1} b / h
    contact_force = softplus( -sigma * (J Q^{-1} b + phi) - 0.1 * sigma * J Q^{-1} b / h )
    v_contact     = Q^{-1} J^T contact_force / h
    v             = v_non_contact + v_contact

要点：

1. FREE 用 `softplus` 把接触力写成 `(J Q^{-1} b + phi)` 的**软函数**，再经 `Q^{-1} J^T` 回到速度。
   这是"互补自由"的核心——它允许约束被违反，并为之付出软代价。
2. `b` 中**包含物体质量与重力**（`b_o = obj_mass * gravity`）。FREE 的预测器本身是带动力学的。
3. 因此 `jac_mat @ qvel = 0` **从来不是 FREE 的约束**，`A_h x = -J_h dq` 是本项目的错误简化。
   用它评分，测的是**模型失配**，不是"接触模式对不对"。

## B.2 实测：该判据在任何时间尺度上都没有判别力

| 尺度 | 归一化 consistency | adequacy | 退化表现 |
|---|---|---|---|
| 控制区间位移（~0.2 rad） | 0.42–1.05；第 6/7 帧 1e8 | ~1.0（预测≈0） | 加伪接触 / 松开切向 **均不可分** |
| 单物理步（dt=0.002 s） | 1.0–1.8 | 0.93–1.85 | `normal_only` 在多数帧 **优于**真值集 |

`normal_only`（只保留法向行）consistent 残差比真值集更低，说明判据系统性偏好**更松的约束**。
真值接触集 `rank(A_true)` = 3,6,5,6,6,6,6,6 —— **2/8 帧不满秩**。

装备结论：**该项证伪结果不是关于接触歧义的，而是关于本项目早期线性化表示的。**
它排除的搜索空间是：任何"用 FREE 约束的全局残差做假设评分"的做法。

## B.3 重建方案（尚未验证）

**方案 1（首选，逐接触瞬时判据，物理正确）**

对每个候选接触 c 计算瞬时相对速度 `c = jac_c @ qvel`，按模式判：

- `STICK`：`||c|| ≈ 0`
- `SLIDE`：法向分量 `c_n ≈ 0`，切向允许非零
- `FREE`：`c_n > 0`（分离）

逐接触判定后组合成假设相容性，**不做**全局残差最小化。

限制：需要**物体瞬时速度**，而它在控制器白名单之外（`object_velocity_mujoco` 目前是 label）。
因此该判据的**诊断价值**与**可部署性**必须分开陈述。

**方案 2（准静态力平衡，有明确有效域）**

仅当物体接近静止时成立。实测第 6–8 帧 `|x| ~ 1e-5`（近静止，适用），
第 4/5 帧 `|x| ~ 2.6–3.2`（远离静止，不适用）。
这套判据的价值在于它的**有效域可以被量化**——按 `|object velocity|` 分桶即可得到边界。

**方案 3（前向仿真假设检验）**

用 MuJoCo 按假设相关的接触配置做前向仿真，比较预测与观测。诚实，但**放弃"不需要动力学"**。

## B.4 纪律

- 在方案 1 或 2 给出可复现的判别力证据之前，**不得**声称 L1 通过。
- 任何替代预测器都必须写明它使用了哪些量；若用了质量/惯量/摩擦，则与"方法不需要动力学"的主张冲突，
  必须在报告中显式标记 `USES: object dynamics`。
